# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff_within_plan | Every changed file and hunk in the Candidate PR's Diff, read against the files, changes, and Not-in-scope items in Plan context, plus the plan's Deviations if any | Every change in the diff is named by the plan (the file or its folder) or recorded in Deviations or the description with a reason it was needed for this issue; nothing in the diff touches what the plan puts out of scope | required |
| plan_delivered | Each step and file the plan in Plan context commits to, read against the Diff | Every step the plan commits to appears in the diff, or its absence is stated openly in the Description or the plan's Deviations | required |
| description_matches_diff | Each statement in the Title and Description, read against the Diff | No claim in the title or description is contradicted by the diff (a claimed change that is missing, or a fidelity claim such as "exactly" or "no changes beyond" that the diff breaks), and the diff makes no behavior change the description leaves unmentioned; tests, code comments, changelog lines, and helpers that carry out a described change count as covered; loose wording the diff does not contradict (such as "one function touched" when a helper is added for that change) passes | required |
| claims_backed_by_diff | Each checklist or Testing item the Description marks done (tests added, changelog added, docs updated), read against the Diff | Every item marked done has a file or hunk in the diff that delivers it (a test claimed for a case passes when a test in the diff exercises that case, even if several cases share one test); fails when a claimed test, changelog entry, or doc has no matching file or hunk at all | required |
| evidence_observable | The Test evidence, read against every repro or failure mode the Test plan in Plan context names as proof of the fix, with Plan context's repro evidence as the before | The issue's own repro is reported as re-run on the change, with its command or steps and a concrete observed after result (printed output, or a specific observation such as "no error, searches normally" or "browser shows the full URL") that differs from the before the way the test plan predicts; every other repro or failure mode the test plan names as proof is reported with its observed result, or its omission is stated with a reason in the Description; fails when evidence is absent, when the after is only a verdict with no observation ("works", "fixed", "should be fine", "looks right"), when the issue's repro was not re-run, or when a named failure mode is silently left out; controls and smoke checks may be stated briefly | required |
| repo_checks_run | The Test evidence and Description, read against every test suite or check the Test plan names and every check Repo facts (or, live, the PR template and CONTRIBUTING.md) list | Every such suite or check is reported with its command or name and its outcome, printed or stated specifically (such as "cargo test -p ignore passes (214 tests)" or "fmt and clippy clean"); fails when a named suite or check is not mentioned at all or is reported only vaguely ("tests should pass", "ran the tests"); a failing or empty result (such as "no tests ran") passes if reported honestly; passes if neither the plan nor the repo names any | required |
| no_debris | Every hunk in the Diff | The diff contains no debug output lines, commented-out code, whitespace-only or formatting-only edits to unrelated lines, or edits unrelated to the issue | required |
| standards_asks_met | The Description and Commits, read against every PR ask in Repo facts (or, live, every section of the PR template and every ask in CONTRIBUTING.md) | Every ask the repo states is met: each template section present and filled with content true of this PR (N/A with a reason counts), and the issue referenced in the form the repo asks for; passes if the repo states no asks beyond referencing the issue and the issue is referenced | required |
| ai_disclosure | The Description, read against the AI policy in Repo facts (or, live, CONTRIBUTING.md and the course rule that every PR discloses AI use) | Where an AI policy applies, the Description states in the author's own words how AI was used, as the policy requires; passes if no AI policy applies | required |
| branch_name | The branch name, if the package shows one | It has a type prefix (fix/, docs/, feat/, test/, refactor/, perf/, chore/), the issue number, and a short description | preferred |

## Verdict rule

Accept if every required check passes. Preferred checks never change the verdict. Unclear counts as fail. A shortfall or deviation that the Description or the plan's Deviations states openly is not a failure of any check: grade the disclosure as the evidence and pass it.
